# أبصار الإسلام — مكتبة الشيخ

تطبيق ويب تقدّمي (PWA) يجمع كتب الشيخ ودروسه وبرامجه ومقالاته، ويُستضاف على GitHub Pages. والموقع نفسه **مصدر البيانات** لتطبيقات الجوال (انظر «تطبيقات الجوال» و[docs/data-format.md](docs/data-format.md)).

لا يحتاج أي أداة بناء: HTML وCSS وJavaScript خالصة.

## بنية المشروع

| الملف | الوظيفة |
|---|---|
| `index.html`, `styles.css`, `app.js` | واجهة التطبيق: الرئيسية، البرامج، الأسابيع، المرئيات، الكتب، البحث، المحفوظات |
| `sw.js`, `manifest.webmanifest`, `icons/` | التثبيت كتطبيق والعمل دون اتصال |
| `data/library.json` | **يُعدَّل يدوياً**: بيانات الموقع، وتعريف البرامج، ومواد إضافية (كتب…) |
| `data/sources.json` | **يُعدَّل يدوياً**: قنوات تليجرام ويوتيوب وربط كل قناة ببرنامجها |
| `data/tg/index.json` | يُولَّد تلقائياً: فهرس القنوات، أحدث المنشورات، الوسوم، الأسابيع، الكتب |
| `data/tg/<قناة>/<k>.json` | يُولَّد تلقائياً: المنشورات مقسّمة (500 منشور في الملف) لتبقى خفيفة على الجوال |
| `data/youtube.json` | يُولَّد تلقائياً: فيديوهات يوتيوب وقوائم التشغيل |
| `scripts/sync_telegram.py` | يجلب منشورات القنوات، ويصنّف الكتب والملفات والمرئيات، ويربط منشورات البرنامج بأسابيعها |
| `scripts/sync_youtube.py` | يجلب فيديوهات القناة وقوائم التشغيل |
| `scripts/sync_files.py` | ينسخ الكتب والملفات والصوتيات من تليجرام إلى Cloudflare R2 |
| `data/tg/files.json` | يُولَّد تلقائياً: حالة النسخ إلى R2 (ما رُفع، ورابطه، وحجمه) |
| `.github/workflows/sync.yml` | يشغّل المزامنة كل نصف ساعة (ومع الإشارة الفورية) ويحفظ الجديد تلقائياً |
| `.github/workflows/r2-archive.yml` | يُشغَّل يدوياً مرة واحدة لنسخ أرشيف الملفات القديم كله إلى R2 |
| `automation/cloudflare-worker.js` | Worker يراقب القنوات كل دقيقة ويطلق المزامنة فوراً |
| `automation/files-worker.js` | Worker يقدّم الملفات من حاوية R2 |
| `docs/data-format.md` | **توثيق صيغة البيانات** للتطبيقات الخارجية |

### كيف يُرتَّب المحتوى تلقائياً

- **البرامج**: كل قناة تليجرام مربوطة ببرنامج عبر `program` في `sources.json`.
- **الأسابيع** (برنامج حفظ القرآن): الأسبوع يبدأ بمنشور «مقرر الأسبوع N» وينتهي بـ«اختبار الأسبوع N»، وكل ما بينهما من مقاطع وملفات يُنسب إليه، ويُربط بقائمة يوتيوب التي تحمل الرقم نفسه.
- **الكتب والملفات**: كل PDF يُنشر في القنوات يُصنَّف: ملفات المقاطع الأسبوعية (تفسير، معاني، وقف وابتداء…) تذهب إلى أسابيعها، والباقي إلى قسم الكتب، ويُحذف المكرر بين القنوات.
- **المرئيات**: روابط يوتيوب المنشورة في تليجرام تأخذ عنوانها من يوتيوب.

## التشغيل محلياً

```bash
python3 -m http.server 8765
```

ثم افتح http://localhost:8765

## المزامنة

1. ضع أسماء القنوات في `data/sources.json`.
2. أول مرة، اجلب أرشيف تليجرام كاملاً:

```bash
python3 scripts/sync_telegram.py --full
```

3. لجلب **كل** فيديوهات يوتيوب وكامل محتوى قوائم التشغيل (لا آخر 15 فقط)، أنشئ مفتاح YouTube Data API v3 مجانياً من Google Cloud، وأضفه في إعدادات المستودع على GitHub: `Settings → Secrets → Actions` باسم `YOUTUBE_API_KEY`.

بعد ذلك يتولى GitHub Actions المزامنة كل نصف ساعة دون تدخل.

> المزامنة من تليجرام تعمل مع **القنوات العامة** فقط (التي لها رابط `t.me/اسم`). القنوات الخاصة تحتاج طريقة أخرى عبر Telegram API.

## الملفات دون تليجرام (Cloudflare R2)

تليجرام محجوب أو متعثر في بعض الدول، فلا تُفتح منه الملفات لكثير من المستخدمين. لذلك تُنسخ كل الكتب والملفات والصوتيات آلياً إلى حاوية **Cloudflare R2**، ويقدّمها Worker على رابط ثابت. ويبقى رابط تليجرام احتياطاً ثانوياً.

- **طريقة التنزيل:** البوت المشرف في القنوات (Bot API) يعيد توجيه المنشور إلى محادثة التخزين، فيأخذ معرّف الملف، ثم يحذف الرسالة وينزّل الملف. حدّ Bot API هو ٢٠ ميجابايت للملف.
- **منع التكرار:** يُسمّى الملف في R2 ببصمة محتواه (`f/<sha256>.pdf`). فالملف المنشور في عدة قنوات يُحفظ مرة واحدة، ولا يُعاد رفع شيء رُفع من قبل.
- **الملفات الأكبر من ٢٠ ميجابايت** (نادرة): يطبع السكربت اسماً مقترحاً لكل ملف. يُرفع الملف بهذا الاسم من لوحة R2، ثم يُضاف إلى `files.manual` في `data/sources.json`.
- **عنوان التقديم:** `files.base_url` في `data/sources.json`. تغييره، كالانتقال إلى نطاق خاص، يغيّر روابط كل الملفات في المزامنة التالية دون إعادة رفع.
- **الأرشيف القديم:** شغّل «نسخ أرشيف الملفات إلى R2» من تبويب Actions مرة واحدة. وإن انقطع، فتشغيله ثانية يكمل من حيث توقف.
- **الجديد:** تنسخه المزامنة الدورية والفورية تلقائياً.

**الأسرار المطلوبة** في `Settings → Secrets and variables → Actions`، ولا يُكتب أي مفتاح في الكود:

| السر | القيمة |
|---|---|
| `TG_BOT_TOKEN` | مفتاح البوت من @BotFather (البوت مشرف في القنوات) |
| `TG_STORAGE_CHAT_ID` | رقم المحادثة التي يعيد البوت التوجيه إليها مؤقتاً (محادثة صاحب الموقع مع البوت) |
| `R2_ACCOUNT_ID` | معرّف حساب Cloudflare |
| `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` | مفتاح R2 API بصلاحية Object Read & Write على الحاوية |
| `R2_BUCKET` | اسم الحاوية (`absar-files`) |
| `YOUTUBE_API_KEY` | مفتاح YouTube Data API v3 |

## تطبيقات الجوال

- **iOS: تطبيق أصلي بـ Flutter، لا تغليف للموقع.** ترفض أبل التطبيق الذي هو موقع داخل إطار (WebView)، بموجب **القاعدة 4.2: الحد الأدنى من الوظائف** في إرشادات مراجعة App Store. لذلك يُبنى تطبيق iOS أصلياً بـ Flutter، يقرأ بيانات الموقع بصيغتها الموثّقة في [docs/data-format.md](docs/data-format.md)، ويعرضها بواجهة أصلية، ويفتح الملفات من روابط R2.
- **أندرويد:** خياران:
  1. **TWA (Trusted Web Activity):** يغلّف الموقع نفسه، فيُنشر سريعاً على Google Play بلا كود إضافي، ويتحدّث مع الموقع تلقائياً.
  2. **تطبيق Flutter نفسه** المبني لـ iOS، فتتوحد التجربة على المنصتين.
- **مصدر البيانات واحد** في الحالتين: ملفات JSON في هذا المستودع، تُحدَّث آلياً ولا تحتاج خادماً.

1. ارفع المجلد إلى مستودع على GitHub.

3. فعّل Actions، وشغّل «مزامنة تليجرام ويوتيوب» يدوياً مرة مع خيار الأرشيف الكامل.
